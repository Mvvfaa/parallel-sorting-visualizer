Quick Sort — Time & Space Complexity

Best Case
O(n log n)
Pivot always splits array into two equal halves
Average Case
O(n log n)
Random pivots yield balanced partitions on average
Worst Case
O(n²)
Pivot is always the smallest or largest element
Parallel (p threads)
O(n log n / p)
Each thread sorts an independent sub-segment
Space
O(log n)
Recursive call stack depth; in-place — no extra array

How it works: Quick Sort picks a pivot, partitions elements into smaller-left / larger-right sub-arrays, then recurses on each half. In the parallel version, independent sub-problems are handed off to separate threads simultaneously, reducing wall-clock time by roughly p× (where p = thread count) on balanced inputs. The Lomuto partition scheme is used here: the last element is chosen as pivot, and a single scan places it in its final sorted position. Quick Sort is in-place (O(log n) stack space) but not stable — equal elements may change relative order.
